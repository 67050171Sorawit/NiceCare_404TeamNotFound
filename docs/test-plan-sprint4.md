## test plan sprint4

### Who — จะทดสอบกับใคร (Target Users) 
1: นักศึกษาที่อาศัยอยู่กับผู้สูงอายุ (ตัวแทนผู้ดูแลรุ่นใหม่/คุ้นเคยเทคโนโลยี)

2: ผู้ปกครองอายุ 40-60 ปี (ตัวแทนผู้ดูแลกลุ่มหลัก/มีประสบการณ์ดูแลจริง)

### What — จะให้เขาทำ task อะไร (User Tasks)Task 
1: เปิดค้างไว้ ทำกิจกรรมปกติ ---> ทักทายทันทีเมื่อเห็นสิ่งผิดปกติ (เช็กความเร็วในการรับรู้แถบสีแดง FALL DETECTED)

2: เดินกลับมาดูหน้าจอ ---> มองหาและบอกเวลา (Timestamp) ที่ผู้สูงอายุล้ม (เช็กความยากง่ายในการหาข้อมูลเวลา)

3: สังเกตหน้าจอเตือนภัย ---> อธิบายว่าจะทำอย่างไรต่อ (เช็กความเข้าใจในความหมายของสิ่งที่ UI แสดงผล)

### How — จะเก็บ feedback อย่างไร (Method)Think Aloud Protocol
ให้ผู้ใช้ส่งเสียงพูดบ่นทุกสิ่งที่คิดในหัวออกมาดัง ๆ ตลอดการคลิกใช้งานObservation Method: สังเกตและจดพฤติกรรมหน้างานลงกระดาษ (Paper Note) เจาะลึกจุดที่ผู้ใช้หยุดชะงัก, มองหาไม่เจอ หรือกดคลิกสุ่ม

### Evidence — จะมีหลักฐานอะไร (Evidence)คลิปวิดีโอ & ภาพถ่าย
บันทึกเวลาการรับรู้ภัย (Time-to-Perception Log): ตัวเลขสถิติจับเวลาจริง (เป็นวินาที) นับตั้งแต่ระบบเปลี่ยนสถานะเป็นสีแดงบน Firebase จนถึงวินาทีที่ผู้ใช้ร้องทักตอบสนองใน Task 1 เพื่อใช้พิสูจน์สมมติฐาน 3 วินาทีของทีม

### Decision — จะใช้ feedback เพื่อตัดสินใจอะไรใน Sprint 5 (Action Item)
Redesign Layout : ตัดสินใจรื้อและจัดโซนหน้า Dashboard ใหม่ หากผู้ใช้ส่วนใหญ่ยังสับสนและกวาดสายตาไร้ทิศทาง (User 2)

UI Optimization : ปรับขนาดปุ่ม เปลี่ยนชื่อปุ่มควบคุมให้เข้าใจง่ายขึ้น (Action Verb) หลังพบว่าผู้ใช้หาปุ่มกดไม่เจอ (User 1) หรือใช้งานเบื้องต้นไม่เป็นเลย (User 3)
